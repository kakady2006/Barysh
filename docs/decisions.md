# Решения и отступления от ТЗ

Здесь фиксируется всё, что меняет `TZ.md`. При расхождении этот файл главнее.

## 2026-10-25 — по итогам изучения API Forever

**API.** Аукцион Forever работает на современном `C_AuctionHouse` (как retail), а не на классическом `QueryAuctionItems`.

1. **Сделки по товарам.** Стакающиеся товары (ткань, травы, руда) — commodities: покупатель указывает количество, сервер продаёт самые дешёвые штуки первыми, выбрать конкретный лот нельзя. В «Сделках» товар — одна строка «купить N штук до цены X»; ценность и прибыль считаются по лестнице цен; один клик — покупка N штук (`StartCommoditiesPurchase` → подтверждение).
2. **Сделки по вещам.** Номер лота (auctionID) есть только в поиске по предмету, не в полном скане. При выборе строки аддон сам ищет предмет, кнопка «Купить» становится активной, когда лот найден.
3. **Сравнение лотов между сканами.** Ключ — «предмет + количество + цена». Остаток срока может только уменьшаться (переход в следующую корзину — тот же лот). Лоты с одинаковым ключом сопоставляются как мультимножество.
4. **Оценка продаж по исчезнувшим лотам.**
   - Остаток «больше 12 ч» или «2–12 ч» → продан.
   - «30 мин – 2 ч» → неясно, в скорость продаж не идёт.
   - «Меньше 30 мин» → истёк.
   - Если между сканами прошло больше, чем лоту оставалось как минимум (например, 3 часа для лота «2–12 ч»), «продан» меняется на «неясно»: лот мог истечь сам. Так долгие перерывы в сканах не раздувают скорость продаж.
5. **Пачки при выставлении.** Товар выставляется одним лотом: покупатель всё равно берёт любое количество. Пачки 20/40 — опция, по умолчанию выключена.
6. **Цена выставления при равной цене.** Утверждение «при равной цене первым продаётся новый лот» не подтверждено. До проверки в игре — минимальная цена рынка без перебивания.
7. **Распыл.** В Forever навык Наложения чар не нужен: с 1 уровня распыляются вещи любого уровня. Навык не проверяем. Таблица распыла — по Classic, сверяется в игре.
8. **Market.lua.** Лежит в `Barysh/Data/`, указан в TOC с первого дня, в git не попадает; заглушка — `Market.default.lua`.

## Технические решения

- **Тесты:** pytest + lupa (Lua 5.1 внутри Python).
- **Библиотеки:** без Ace3. Профили, события и модули — свои. Сжатие строк импорта — `C_EncodingUtil` (проверить в игре), запасной вариант — LibDeflate.
- **Ошибки аддона:** BaryshSync создаёт один GitHub Issue на уникальную ошибку (хэш сообщения и первой строки стека); повторы — счётчиком в комментарии.
- **TOC:** один файл `Barysh.toc` с `## Interface: 16001` (как у auxForever, сверить). Суффикс `_Forever` клиент тоже понимает, но для одного клиента он не нужен.
- **Установка:** папка `Barysh` из репозитория подключается в `Interface\AddOns` ссылкой-junction (`tools/install.ps1`).

## Обмен данными аддон ↔ BaryshSync

- Аддон пишет в `BaryshDB.outbox` изменения каждого скана: `a` — новые лоты, `d` — исчезнувшие с вердиктом (s/u/e), `r` — уменьшенные стаки, `s` — цена скана, количество и минимум. Пишет только при включённом модуле «Связь с ПК».
- BaryshSync импортирует их (повторный импорт того же скана ничего не меняет), считает статистику и пишет `Data/Market.lua` с полем `ack`: до какого скана, операции учёта и ошибки всё сохранено.
- Игра перечитывает `Market.lua` только при следующем `/reload`. Поэтому данные с ПК видны со второго «Сохранить», а `outbox` чистится на шаг позже — это нормально.
- Данные BaryshSync (база, копии, лог) — в `%LOCALAPPDATA%\BaryshSync`, не в репозитории.

## 2026-10-26 — всё, что можно без игры

**Сделки**
- Покупка товара: первый клик запрашивает цену (`StartCommoditiesPurchase`), игра называет итог. Если он не дороже строки, кнопка становится «Да, купить», второй клик подтверждает. Если дороже — покупка отменяется с сообщением «Цена выросла». Подтверждение тоже может требовать клика, а проверить это до запуска нельзя. Если в игре подтверждение работает без клика, сделаю покупку в один клик.
- Покупка вещи: при выборе строки аддон ищет лот поиском по предмету (без клика). Кнопка становится «Купить», когда лот найден; клик — `PlaceBid`.
- Сколько купить: выбирается количество с наибольшей общей прибылью. Дешёвый лот, который «держит» цену, может войти в покупку даже в минус, если после него цена продажи растёт.
- Перепродажа без данных о скорости продаж не предлагается. «Новый товар» (меньше 10 сканов): ориентир — среднее 2-го и 3-го лота.
- Депозит в расчётах — оценка: 15% цены торговца за 8 ч, на нейтральном ×5 (`VERIFY`). В игре депозит при продаже возвращается, но по ТЗ он вычитается: так оценка осторожнее.
- Один предмет — один тип, с наибольшей общей прибылью.
- Подсветка лотов в стандартном окне аукциона отложена до проверки в игре: она зависит от фреймов Blizzard в клиенте Forever.

**Продажи**
- Товар выставляется одним лотом. Пачки 20/40 — настройка. «Мелкие пачки для крафтеров» не делаем: покупатель и так берёт любое количество.
- Срок 24 ч, если по скорости продаж всё, что стоит дешевле или так же, плюс наш лот не уйдёт за 8 ч, или лот дороже 50 золотых (настройка). Иначе 8 ч.
- Лоты по той же цене считаются стоящими впереди нас (решение 6 пока не проверено).
- Если игра просит подтвердить цену (`needsConfirmation`), нужен второй клик той же кнопки.
- Депозит вернувшегося лота записывается в учёт как потеря («Вернулось»).

**Торговец, почта, обмен**
- «Продать торговцу» — один клик продаёт весь список, как «Забрать аукционные» забирает все письма аукциона.
- «Оплатить» у письма с наложенным платежом оплачивает его и забирает вложения одним кликом. «Забрать» у письма своего персонажа — то же. Платёж делится на вложения по их рыночной стоимости и идёт в себестоимость.
- Обмен:
  - чары на вещь клиента + золото → услуга;
  - отдал вещь за золото, клиент раньше приносил реагенты → крафт под заказ;
  - отдал недавно скрафченную вещь, но без заказа → вопрос;
  - отдал вещь за золото в остальных случаях → продажа;
  - получил вещь за золото → покупка;
  - получил только вещи → реагенты клиента;
  - получил только золото → вопрос, от незнакомца — с предупреждением.
- Расход по услуге — реагенты из прайса, по крафту — свои реагенты рецепта сверх принесённых клиентом.

**Склад, капитал, рынок**
- Позиция «ниже себестоимости»: рыночная цена после комиссии меньше средней себестоимости. Три дня подряд → подсветка и «Выйти» (в очередь продаж).
- Капитал: товары по рыночной цене после комиссии, без рыночной цены — по цене торговца.
- Рынок: 24 ч и 7 дней — из истории аддона, 30 дней — дневные ряды с ПК (`Market.lua`, поле `series`).
- «Экспорт для анализа»: аддон записывает запрос, файл JSON собирает BaryshSync в `%LOCALAPPDATA%\BaryshSync\exports`.

**Рецепты:** шанс очка навыка по цвету — оценка: оранжевый 1, жёлтый 0,75, зелёный 0,25. План считает, что рецепт даёт не больше 10 очков, пока не сменит цвет.

**Импорт и экспорт:** сжатие — `C_EncodingUtil` (raw DEFLATE), без него строки несжатые. Тот же формат читает и пишет `sync/barysh_sync/importstring.py`. При импорте списка удаляются только записи, пришедшие из прошлого импорта; добавленное вручную остаётся.

**BaryshSync**
- Google Таблица — через сервисный аккаунт, подпись ключа без сторонних библиотек.
  - «Операции» дописываются.
  - «Капитал по дням», «Склад», «Доход по занятиям» перезаписываются целиком.
  - Имена клиентов туда не попадают.
- Значок в трее — через ctypes. Меню: «Синхронизировать сейчас», «Открыть папку данных», «Открыть папку экспорта», «Выход».
