# Barysh — техзадание на аддон для WoW Forever

Oct 25, 2026 · @Кирилл

> Принятые отступления от этого ТЗ (покупка товаров по количеству, сравнение лотов, оценка продаж, пачки, распыл) — в [docs/decisions.md](docs/decisions.md). При расхождении главнее они.

## Коротко

Barysh — аддон для аукциона WoW Forever. Он сам сканирует рынок, считает стоимость распыла и показывает список выгодных покупок с кнопкой «Купить». Вручную ничего считать и записывать не нужно.

Система из трёх частей, четвёртая — позже:

1. **Аддон Barysh** в игре: ядро (скан, цены, распыл, подсказка) и модули, каждый включается галочкой в настройках.
2. **Скрипт BaryshSync на kkd** (Windows): забирает данные аддона после каждого сохранения, складывает в базу, считает статистику и возвращает её аддону. Он же отправляет учёт в Google Таблицу и выкладывает обезличенные логи ошибок в репозиторий.
3. **База SQLite на kkd** — вся история сканов и сделок.
4. **Позже — онлайн-страница** для просмотра рынка с телефона.

Разработка — в Claude Code на kkd, код в публичном репозитории GitHub под лицензией MIT. Логику Claude Code проверяет автотестами; в игре аддоном просто пользуются, а ошибки сами уходят в репозиторий через программу на kkd. Макеты всех окон — на [холсте Barysh](https://claude.ai/artifact/2paavBzZn7sbrNZ6i3yJq2).

## Ограничения игры и правила

Аддон делает всё, что игра разрешает без нажатия, а каждое действие с золотом или предметом — по одному клику игрока. Обход этих правил запрещён.

| Ограничение | Что это значит для Barysh |
| --- | --- |
| Покупка, выставление и отмена лотов требуют реального нажатия (`#hwevent`) | Кнопки «Купить», «Купить следующий», «Выставить следующий», «Снять»: один клик — одно действие |
| Распыл и отправка почты — защищённые действия | Распылитель — защищённая кнопка (SecureActionButton), её цель меняется вне боя после каждого распыла |
| Аддон не пишет файлы и не выходит в сеть | Данные попадают на диск только при `/reload` или выходе из игры (SavedVariables). Кнопка «Сохранить» = `/reload` |
| Полный скан (`C_AuctionHouse.ReplicateItems`) — раз в 15 минут и только при открытом окне аукциона | Режимы скана: по кнопке, при открытии, каждые 15 минут, быстрый по списку. Нужно ли нажатие для запуска скана — проверить 5 ноября; если да, таймер превращается в звуковой сигнал |
| Через \~30 минут бездействия игра выкидывает из мира | Обхода AFK-кика нет. При выходе данные сохраняются сами, и программа на kkd их забирает |
| Клиент Forever — современный API с ограничениями Midnight в бою | Боевые функции не нужны; на аукцион, почту и сумки ограничения почти не влияют |
| Беты нет, документация — [warcraft.wiki.gg, раздел Forever](https://warcraft.wiki.gg/wiki/World_of_Warcraft_API) | Пишем по документации, первая проверка в игре — 5 ноября |

Запрещено в аддоне: автоматические сообщения в чат, анти-AFK, автопокупка без клика, автоматический приём писем не от аукционного дома.

## Архитектура и репозиторий

Один аддон: ядро плюс модули, каждый модуль выключается целиком или по отдельным функциям. Выключенный модуль не подписывается на события и не держит данные в памяти.

Игра пишет файл только при сохранении; BaryshSync разносит данные по базе, таблице и GitHub и возвращает аддону статистику, которую тот читает при следующем /reload.

**Модули и группы настроек**

| Группа | Модули | Можно выключить |
| --- | --- | --- |
| Основа | Скан и цены, Подсказка к предмету | Скан — нет; подсказку — да |
| Торговля | Сделки, Продажи, Склад, Нейтральный аукцион | Да, и каждую функцию внутри |
| Ремесло и услуги | Распылитель, Выгода рецептов, Обмен и услуги | Да |
| Деньги | Почта, Учёт и капитал | Да |
| Служебное | Списки товаров, Импорт и экспорт, Связь с программой на ПК | Связь — да |

**Требования к коду**

- Lua под клиент Forever (`## Interface:` — номер версии клиента, сверить 5 ноября). Без внешних библиотек, кроме стандартных Ace3 и LibDataBroker, если понадобятся.
- Все строки интерфейса — через таблицу переводов (`Locales/ruRU.lua`, `enUS.lua`). Сейчас заполнен русский, английский — запасной.
- Названия предметов берутся из клиента, хранение — по ID предмета.
- Настройки — профили: общий для аккаунта или свой у персонажа.
- Никаких личных имён и значений в коде. Персональные списки приходят импортом.
- Тяжёлые операции (разбор скана) — порциями по кадрам, чтобы игра не подвисала.

**Репозиторий**

- GitHub, публичный, `Barysh`, лицензия MIT. Создаёт Claude Code на kkd через `gh`, пользователь подключает.
- Структура: `Barysh/` (аддон), `sync/` (программа на kkd), `tests/` (автотесты Lua с имитацией API), `docs/`.
- В git не попадают SavedVariables, база SQLite, ключи Google и любые файлы с именами персонажей.
- Логи ошибок, которые выкладывает программа на kkd, обезличены: имена персонажей и игроков заменены на условные.

## Ядро: скан, цены, подсказка

Ядро сканирует аукцион, считает рыночную цену, скорость продаж и стоимость распыла каждого предмета и показывает их в подсказке.

**Скан.** Четыре режима, каждый включается отдельно:

1. По кнопке «Полный скан».
2. При открытии окна аукциона.
3. Каждые 15 минут, пока окно аукциона открыто.
4. Быстрый скан по списку «Быстрый скан» — только отслеживаемые товары, без лимита 15 минут.

Аукционы хранятся раздельно: фракционный и нейтральный (Прибамбасск, Пиратская Бухта, Круговзор). Аддон определяет, у какого стоит игрок. Комиссия: фракционный 5%, нейтральный 15%.

**Запись только изменений.** Скан проходит весь аукцион, но сохраняется только разница с прошлым сканом: новые лоты, исчезнувшие лоты и предметы, у которых изменились цена или количество. Неизменившееся не перезаписывается. Лот сравнивается по ключу «предмет + количество + цена»; остаток срока может только уменьшаться. Исчезнувшие лоты — это и есть исходные данные для оценки продаж. Сам проход по аукциону быстрее не станет (его скорость задаёт игра), но разбор, файл сохранения и запись в базу станут в разы меньше.

В аддоне — сводка по предмету за последние 7 дней, обновляется только при изменениях. В базу на kkd уходят изменения лотов; полное состояние рынка на любой момент восстанавливается из них.

**Цена одного скана** — медиана цены среди самых дешёвых 15% штук на рынке (по количеству). Одиночный лот за 2 серебра среди сотни по 1 золотому её почти не сдвигает, задранные цены не влияют.

**Рыночная цена** — медиана цен сканов за 7 дней, последние 3 дня с весом 2. История в базе хранится вся; выбросы исключаются только из расчёта.

**Скорость продаж (оценка):**

- Лот исчез между сканами, а остаток срока был «больше 12 часов» или «до 12 часов» → считается проданным.
- Исчез с остатком «30 минут – 2 часа» → неясно, в скорость не идёт.
- Исчез с остатком «меньше 30 минут» → считается истёкшим.
- Стакающиеся товары: уменьшение количества в лоте → продано.
- Свои продажи — точно, по письмам аукционного дома.
- В интерфейсе подписывается «оценка».

**Новый товар** (меньше \~10 сканов) не скрывается: ориентир — второй-третий лот на рынке, метка «новый, цена формируется».

**Распыл.** Таблица распыла Forever (требуемый уровень × качество × броня/оружие → пыль, сущность, осколок с вероятностями) хранится в аддоне.

```latex
V = 0.75 \cdot D \cdot P_D + 0.20 \cdot E \cdot P_E + 0.05 \cdot P_S
```

Для оружия 0,75 и 0,20 меняются местами; синие вещи всегда дают осколок. Цены пыли, сущностей и осколков — рыночные.

**Подсказка к предмету.** Коротко: цена на аукционе и обычная, распыл, продаж в день, себестоимость у игрока. По Shift: минимум и медиана за 7 дней, цена на нейтральном аукционе, разбор распыла по исходам, лучший вариант (продать, распылить, торговцу) и «покупать дешевле».

## Сделки

Список лотов, которые выгодно купить, отсортированный по прибыли в день. Окно прилипает к правому краю окна аукциона; те же лоты подсвечиваются в стандартном окне.

| Тип | Условие | Ценность |
| --- | --- | --- |
| Распыл | Цена лота ниже ценности распыла с учётом комиссии и минимальной прибыли | V по формуле распыла |
| Перепродажа | Цена заметно ниже ожидаемой цены продажи | Ожидаемая цена продажи |
| Склад | Товар из списка «Склад», цена ниже «Покупать до» или рыночной, не выше потолка | Рыночная цена |
| Сырьё для крафта | Реагенты дешевле готового предмета из известного рецепта | Цена готового предмета минус остальные реагенты |
| Арбитраж | Разница между фракционным и нейтральным аукционом больше двух комиссий | Цена на другом аукционе |
| Лёгкие деньги | Цена лота ниже цены продажи торговцу | Цена торговца, без комиссии |

**Ожидаемая цена продажи** = меньшее из двух: рыночная цена или цена следующего лота после покупки этого. Минус комиссия и депозит.

**Прибыль в день** = прибыль за штуку × сколько штук реально продашь за день (по скорости продаж, не больше купленного количества). Для «Лёгких денег» — «сразу».

**Порог:** прибыль после комиссии больше нуля и не меньше «Мин. прибыль за лот» (по умолчанию 1 серебро). Лимитов на склад нет; у позиции показывается, за сколько дней она распродастся.

**Осторожность оценки** (настройка): обычная — как выше; осторожная — 35-й процентиль цены вместо медианы; смелая — 65-й.

Один предмет попадает только в один тип — тот, где он выгоднее всего.

**Интерфейс:** фильтры по типам со счётчиками, «по карману», колонки «Предмет · Тип · Цена · Ценность · Прибыль · В день», кнопка «Купить» в строке и «Купить следующий» внизу. Итог: сколько стоит купить всё и какая прибыль.

**Оповещения:** звук при сделке дороже порога (по умолчанию 5 золотых), всплывающее окно (выкл.), сигнал о падении цены на 30%+ за сутки на большом объёме.

## Продажи

Очередь выставления: аддон сам выбирает цену, пачку и срок, игрок жмёт одну кнопку на лот.

**Очередь.** Попадают предметы в сумках, которые выгоднее продать на аукционе, чем распылить или сдать торговцу, плюс вернувшиеся по почте нераспроданные лоты (метка «вернулось»).

- Цена: минимальная на рынке, без перебивания на медяк (при равной цене первым продаётся новый лот), но не ниже себестоимости. Ниже себестоимости — предупреждение.
- Пачки: по 20 и 40 для сырья (под ящики Waylaid Crates) и мелкие для крафтеров; поштучно для вещей.
- Срок: 8 часов, для дорогих и медленных товаров — 24 часа (порог — скорость продаж).
- Показ: депозит за всю очередь и выручка после комиссии.
- Кнопка «Выставить следующий».

**Твои лоты.** По каждому — твоя цена, сколько штук стоит дешевле тебя и состояние:

- Дешевле меньше, чем продаётся за день, → «ок, раскупят первым». Перевыставлять не нужно.
- Дешевле больше дневных продаж → «перебит объёмом» и кнопка «Снять». Перед этим показывается потерянный депозит и цена, по которой лот выставится снова. Снятый лот приходит по почте; после «Забрать аукционные» он сам попадает в очередь с новой ценой. Мгновенного перевыставления нет: игра возвращает снятые лоты только почтой.

## Склад и списки товаров

Склад показывает товары, купленные под будущий спрос: сколько вложено, сколько стоят сейчас и когда продавать.

**Вкладка «Склад».** Сверху: вложено, стоит сейчас, прибыль при продаже по рынку после комиссии. По каждой позиции: количество, средневзвешенная себестоимость, текущая цена, прибыль, за сколько дней уйдёт всё количество, примечание «зачем» (из списка). Позиция ниже себестоимости 3 дня подряд подсвечивается и получает кнопку «Выйти» (в очередь продаж). Кнопка «В продажи» у каждой позиции.

**Себестоимость** — средневзвешенная по каждому предмету: при покупке пересчитывается, при продаже прибыль считается от средней. Учитываются покупки на аукционе, почтой с наложенным платежом и в обмене; распыл переносит стоимость вещи на полученную пыль.

**Списки товаров** (настройки → «Списки товаров»):

| Список | Для чего |
| --- | --- |
| Быстрый скан | Что проверять быстрым сканом |
| Склад | Что копить: «Покупать до» (авто или цена), потолок, примечание «зачем» |
| Не покупать | Исключить из всех сделок |
| Распыл: исключения | Что распылитель не трогает |
| Свои списки | Любые, создаются игроком |

Добавление: перетащить предмет, вставить ссылку, название или ID. У каждой строки — откуда она (вручную или импорт) и кнопка «Убрать».

**Импорт и экспорт строкой.** Формат `!BARYSH:<версия>!<имя>!<данные>`: сжатая сериализация, внутри — ID предметов и параметры. Перед применением аддон показывает разницу (добавится, удалится, изменится) и применяет по кнопке. Экспорт: один список или все настройки. Строки может присылать Claude под стадии сервера или другие игроки.

## Учёт, почта, обмены и услуги

Все деньги и предметы, которые входят и выходят, записываются автоматически; игрок только подтверждает неясные случаи.

**Учёт и капитал.** Операции: покупка и продажа на аукционе, истёкший лот (потерянный депозит), распыл, продажа торговцу, крафт, почта с наложенным платежом, обмен, услуга. По каждой: время, тип, предмет, количество, сумма, прибыль. Периоды: сегодня, неделя, месяц, всё; фильтры по типам; экспорт за период.

Капитал считается по всем персонажам аккаунта: золото, сумки, банки, почта, выставленные лоты. Товары — по рыночной цене после комиссии. Данные персонажа обновляются, когда на нём заходят в игру.

**Вкладка «Обзор»:** капитал и его состав, золото по персонажам, прибыль и число сделок за сегодня, доход в час (время в игре) и по занятиям за неделю, блок «Требует внимания» (старые данные рынка, перебитые лоты, письма аукциона, позиции склада ниже себестоимости) с переходами.

**Почта.**

- Кнопка «Забрать аукционные»: только письма аукционного дома (продано, куплено, истекло). Выручка и предметы — в учёт, истёкшие лоты — в очередь продаж.
- Остальные письма аддон никогда не забирает сам, а показывает списком.
- Золото от незнакомца (не персонаж аккаунта, не согильдиец): предупреждение о риске бана за покупку золота и кнопка «Вернуть отправителю».
- Наложенный платёж: цена письма, рыночная стоимость вложений, вердикт «выгодно / невыгодно» и прибыль. Кнопки «Вернуть» и «Оплатить и принять»; сделка попадает в учёт.
- Письма от своих персонажей: кнопка «Забрать».

**Обмен.** Аддон читает окно обмена: предметы и золото с обеих сторон и нижний слот «Не будет обменяно». После успешного обмена он определяет тип:

| Что произошло | Как записывается |
| --- | --- |
| Чары на вещь клиента в нижнем слоте, получено золото | Услуга: выручка — золото, расход — только свои реагенты |
| Клиент раньше дал реагенты, теперь получил созданную вещь и заплатил | Крафт под заказ: связывается по имени клиента, расход — свои добавленные реагенты |
| Вещь отдана за золото | Продажа без комиссии |
| Вещь получена за золото | Покупка, в себестоимость |
| Золото без встречной передачи | Вопрос; от незнакомца — предупреждение |

Понятные обмены записываются сами, с коротким сообщением и кнопкой «Исправить». Неясные — окно «Что это было?» с вариантами, которые зависят от направления: отдал вещь за золото → «Крафт под заказ / Продажа / Не учитывать»; получил вещь за золото → «Покупка / Не учитывать».

**Прайс услуг:** услуга, цена с реагентами клиента, цена со своими («авто» = цена + рыночная стоимость реагентов). Во время обмена аддон показывает цену по прайсу и совпадает ли положенная сумма.

**Клиенты:** имя, число заказов, сумма, последний заказ; метка «постоянный клиент» в подсказке обмена. Имена хранятся только локально.

## Ремесло, торговец и рынок

**Распылитель.** Одна кнопка (и клавиша, по умолчанию F): каждое нажатие распыляет следующую вещь из сумок, названия не важны. На кнопке — сколько вещей осталось, в подсказке — следующая вещь. Правила в настройках: качество (зелёные / зелёные и синие), не трогать надетое, вещи из комплектов и список исключений, пропускать вещи, которые выгоднее продать. Результат распыла идёт в учёт.

**Выгода рецептов.** Панель рядом с окном профессии, по каждому рецепту: цвет очка навыка, стоимость реагентов, цена продажи (аукцион, распыл или торговец — что выгоднее), прибыль после комиссии, цена одного очка навыка. Внизу — план прокачки до следующего порога учителя: порядок рецептов, стоимость реагентов, сколько вернётся от продажи крафта, итог. Кнопки «Список покупок» (в быстрый скан и сделки «Сырьё») и «Сделать следующее». Рецепты читаются из окна профессии автоматически.

**Торговец.** Цена продажи торговцу берётся из клиента. У торговца — кнопка «Продать торговцу»: продаёт серый хлам, покупки «Лёгких денег» и вещи, которые торговцу сдать выгоднее, чем выставить или распылить. Всё в учёт.

**Вкладка «Рынок».** Поиск товара; график рыночной и минимальной цены и продаж за день (24 ч, 7 дней, 30 дней); аукцион: Орда, нейтральный, оба. Цифры: минимум, рыночная, на рынке, продаётся в день, изменение за период и вывод: один дешёвый лот — демпер, резкий рост количества — массовый сброс. Глубина рынка по уровням цены с подсказкой, за сколько раскупят дешевле заданной цены. Движение за сутки: самые подорожавшие и подешевевшие товары. Кнопки «В список» и «Экспорт для анализа» (файл собирает программа на kkd, его можно отправить Claude).

## Программа BaryshSync на kkd и база

Программа на Python работает в фоне на kkd (Windows) и связывает игру с базой: забирает данные после каждого сохранения и возвращает аддону статистику.

1. **Слежение.** Следит за файлом `WTF/Account/<аккаунт>/SavedVariables/Barysh.lua`. Изменился (после «Сохранить», `/reload` или выхода) → разбирает Lua-таблицу.
2. **База SQLite.** Таблицы: сканы (время, аукцион), лоты (предмет, количество, цена, остаток срока), сводки по предмету, операции учёта, персонажи и капитал, клиенты. Лоты хранятся как изменения (появился, исчез, изменился) с временем скана; размер не ограничиваем.
3. **Расчёты.** Рыночная цена, скорость продаж, тренды за 30 дней и дольше — на Python, по всей истории.
4. **Обратно в игру.** Пишет файл данных `Interface/AddOns/Barysh/Data/Market.lua` (рыночные цены, скорость продаж по предметам). Аддон читает его при следующем `/reload`. Если файлу больше 24 часов, аддон напоминает обновить данные.
5. **Google Таблица.** Новые операции учёта и капитал за день — через Google Sheets API (сервисный аккаунт). Листы: Операции, Капитал по дням, Склад, Доход по занятиям.
6. **Логи ошибок.** Ошибки аддона (стек и версия) обезличиваются и выкладываются в репозиторий как GitHub Issue или файл — Claude Code видит их сам.
7. **Экспорт для анализа.** По запросу из вкладки «Рынок» собирает файл (история цен, объёмы, лоты) для отправки Claude.
8. **Резервные копии** SavedVariables перед каждой обработкой: при вылете игры файл иногда обнуляется.

Запуск — вместе с Windows (планировщик заданий), окно — значок в трее с состоянием «последняя синхронизация».
