# Barysh — правила для Claude Code

Аддон аукциона для WoW Forever + программа BaryshSync на ПК пользователя (kkd, Windows).
Спецификация — `TZ.md`, принятые отступления от неё — `docs/decisions.md` (они главнее ТЗ).

## Общение
- С пользователем — по-русски. Коммиты, имена в коде, комментарии — по-английски; строки интерфейса — через локали.
- Пользователь — координатор: проверяет в игре и присылает замечания. Беты нет; первая проверка в игре — 5 ноября 2026.

## Запреты (правила игры — не обходить никогда)
- Покупка, выставление, отмена лотов, распыл, отправка почты — только по одному клику игрока на одно действие.
- Никаких: автопокупки, анти-AFK, автоматических сообщений в чат, автоматического приёма писем не от аукционного дома.
- Аддон не пишет файлы и не ходит в сеть. Данные уходят только через SavedVariables (`/reload`, выход).
- Код auxForever и других аддонов можно читать как пример, но не копировать.

## Архитектура
```
Barysh/            аддон (папка ставится junction-ссылкой в Interface\AddOns\Barysh, см. tools/install.ps1)
  Barysh.toc       порядок загрузки; новый файл — сразу в TOC (иначе его не увидит ни игра, ни tests/test_load.py)
  Core/            неймспейс, модули, события, настройки и профили, ошибки, порционные задачи, слеш-команды
  Locales/         enUS.lua (база), ruRU.lua (по умолчанию)
  Logic/           ЧИСТЫЙ Lua 5.1: ни одного вызова API игры. Все расчёты — здесь и только с тестами
  Adapters/        тонкий слой над API игры (C_AuctionHouse, почта, сумки, обмен). Всё, что может сломаться на клиенте
  Modules/         функции из ТЗ; каждый модуль регистрируется через ns:NewModule и включается галочкой
  UI/              главное окно (вкладки регистрируются через ns.UI.RegisterTab), виджеты, кнопка у миникарты,
                   окно настроек (Settings.lua), панели у окон игры (Panels.lua)
  Data/            Market.lua пишет BaryshSync (в .gitignore); Market.default.lua — заглушка
sync/barysh_sync/  BaryshSync, Python 3.13 без внешних зависимостей:
                   luadata (разбор SavedVariables), db (SQLite), pricing/stats (та же формула, что в аддоне),
                   market_file, errors (GitHub Issues через gh), backup, app (цикл слежения),
                   sheets + gauth (Google Таблица, сервисный аккаунт), exports («Экспорт для анализа»),
                   importstring (строки !BARYSH, тот же формат, что Logic/Serialize.lua), tray (значок в трее)
tests/             pytest + lupa (Lua 5.1 внутри Python); tests/wow_mock.lua — имитация API игры
sync/tests/        тесты BaryshSync, включая сквозной: аддон → SavedVariables → BaryshSync → Market.lua → аддон
docs/              решения (decisions.md), чек-лист проверки в игре
tools/             install.ps1 (подключить аддон), register-sync-task.ps1 (автозапуск BaryshSync)
```
- `ns.Prices.Item(itemID)` — единственный источник цен для модулей (локальная история + данные с ПК).
- `/barysh probe` пишет в `BaryshDB.probe` факты о клиенте; BaryshSync сохраняет их в таблицу `probe`. Первым делом после запуска игры — смотреть туда.
- Формула рыночной цены живёт в двух местах (`Logic/Pricing.lua` и `sync/barysh_sync/pricing.py`); тест `test_market_price_matches_addon` следит, чтобы они совпадали.
- Каждый файл аддона начинается с `local _, ns = ...`. Глобальных переменных нет, кроме `BaryshDB`, `BaryshCharDB` и слеш-команд.
- Модуль: `local M = ns:NewModule("Name", { group = "trade", canDisable = true, defaultEnabled = true })`, затем `M:OnEnable()` / `M:OnDisable()`. Подписка на события — только `M:RegisterEvent(...)` внутри `OnEnable`. Выключенный модуль не держит данных и подписок.
- Обработчики событий и колбэки — через `ns.Safe`: ошибки попадают в `BaryshDB.errors`, их забирает BaryshSync.
- Тяжёлая обработка — через `ns.Jobs` (порции по кадрам с бюджетом времени).
- Деньги везде в медяках (целые). Предметы — по itemID, названия берутся из клиента.
- Ничего личного в коде: имён персонажей, аккаунтов и путей. Персональные списки приходят импортом.

## Тесты
- `python -m pytest` из корня — должен проходить перед каждым коммитом.
- Новая функция в `Logic/` → тест в `tests/test_<file>.py`. Загрузка всех файлов из TOC проверяется в `tests/test_load.py`.
- В `tests/wow_mock.lua` добавлять только то, что реально есть в API Forever (сверять с warcraft.wiki.gg).

## Что неизвестно до 5 ноября
Список и способ проверки — `docs/ingame-checklist.md`. Пока факт не проверен, он живёт константой в одном месте с комментарием `-- VERIFY:`.

## Git
- Ветка `main`. Коммиты небольшие, сообщение по-английски, в конце — строка Co-Authored-By из системной подсказки.
- В git не попадают: SavedVariables, база SQLite, ключи Google, `sync/config.toml`, `Barysh/Data/Market.lua`, всё с именами персонажей.
